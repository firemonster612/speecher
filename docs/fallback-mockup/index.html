Provider fallbacks

Each role, speech and refinement, gets a chain: a primary provider and up to two fallbacks. Dictation uses the first one that works. When every refinement provider fails, the raw transcript is pasted, as it is today.

Pages

  • Settings, in three layouts to choose from. In each one, a provider with settings of its own gets a card named after it.
    • Ordered list: the chain is one list with move and remove buttons, and an Add a fallback row.
    • Every service, in order: every provider listed once. Ticking one puts it in the chain, and the arrows set the order.
    • Fallbacks page (chosen): today's Service row, plus one button row that opens a subpage with the ordered list. The subpage.
  • Setup assistant: Transcription: an "If ChatGPT Codex is unavailable" section, suggesting a Local model when this computer can run one.
  • Setup assistant: Refinement: the same section, suggesting a Local Runner when one is running. Both setup pages show the same ordered list as the Settings Fallbacks page, inline.
  • Popup outcomes: what the popup says after each kind of fallback.

Decided

  • Speech switches at the start of a dictation and in the middle of one. A stream that drops gets its two reconnects first. After that, the next attempt opens on the next provider and the text so far is kept.
  • Audio the failed provider never confirmed is not sent again, so rule A7 stays. A few words can be lost when a provider fails mid-dictation.
  • A rejected sign-in falls back like any other failure. The outcome line says the sign-in needs fixing and offers Open Accounts.
  • After a fallback, the popup's outcome line names the provider that ran and why the earlier one didn't.
  • The chain is set in Settings and in the setup assistant.
  • These mockups assume the speech Custom Endpoint streams. That fix is in progress separately.

Open questions the mockups take a position on

  • Live status in Settings. Each slot says when its provider can't work right now (offline, no model, runner stopped). That means probing the providers when the page opens.
  • Spoken Language. A fallback that can't listen for the Spoken Language is skipped, for example an English-only Local model while you dictate in French. The alternative is to use it anyway.
  • Outcome with a button. Today only errors have a fix button. The rejected sign-in needs one on a successful outcome.
  • Screenshots. Only OpenAI and Anthropic read the screenshot. Other providers in the chain clean up without it rather than being skipped.
  • Setup assistant. The speech fallback list leaves out Custom Endpoint, because the endpoint is set up in Settings only today.

Not mocked
